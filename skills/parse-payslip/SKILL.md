# 給与明細のパース

## ★最優先 — 書いてはいけないもの

給与明細には次のものが載っています。**JSON に書かないでください。**

- **マイナンバー（個人番号）**
- 基礎年金番号
- 雇用保険被保険者番号
- 振込先の口座番号（下4桁を除く）
- 住所

これらは一度 Git の履歴に入ると取り返しがつきません。
`redact_check` が二重の網を張っていますが、**まずここで書かないことが本線**です。

## 給与は事業の帳簿ではありません

給与所得は事業所得ではないので、**事業の損益には一切現れません**（第5部 §1）。
`income_category` は必ず `"employment"` です。
`Income:Business:*` に流れる出力を作らないでください。

## 検算

**総支給 −（控除の合計）= 手取り** を自分で確かめてから出力します。

## 推測で埋めない

読めない額は `null` にし、`needs_review: true` と `review_reason` を書きます。
**明細に印字された額が正**です。計算して出した値で印字を上書きしないでください。

## 出力

```jsonc
{
  "schema_version": 1,
  "doc_id": "doc_2026-09-05_sampleshop_a1b2c3",
  "type": "payslip",
  "source": { /* 取り込み処理が埋めたもの */ },
  "origin": "paper",
  "employer_id": "emp_sample",
  "income_category": "employment",
  "pay_date": "2026-09-05",
  "period": { "from": "2026-08-01", "to": "2026-08-31" },
  "gross": 120000,
  "earnings": [
    { "name": "基本給", "amount": 115000 },
    { "name": "通勤手当", "amount": 5000 }
  ],
  "deductions": [
    { "name": "健康保険", "amount": 6000, "deduction_type": "social_insurance" },
    { "name": "厚生年金", "amount": 11000, "deduction_type": "social_insurance" },
    { "name": "所得税", "amount": 2400, "deduction_type": "income_tax" },
    { "name": "住民税", "amount": 5000, "deduction_type": "resident_tax" }
  ],
  "net": 95600,
  "commute_allowance": 5000,
  "needs_review": false,
  "review_reason": null
}
```

`deduction_type` は所得控除の集計に使います。**社会保険料と税を混ぜないでください。**
社会保険料は所得控除になりますが、所得税・住民税はなりません。

## 良い例 / 悪い例

### 例1 — マイナンバーが印字されている

```
勤務先  サンプル商店
氏名    ○○ ○○
個人番号  ХХХХ ХХХХ ХХХХ   ← 実際には12桁の数字が印字されています
基本給  115,000
```

**良い**

```jsonc
{
  "employer_id": "emp_sample",
  "gross": 115000,
  "earnings": [ { "name": "基本給", "amount": 115000 } ]
}
```

個人番号も氏名も書きません。**必要ないからです。**

**悪い**

```jsonc
{ "notes": "個人番号 XXXX-XXXX-XXXX が記載されていました" }
```

`notes` に書けば安全、ということはありません。
**同じファイルの同じリポジトリに入ります。**「記載があった」という事実すら書く必要がありません。

### 例2 — 検算が合わない

総支給 120,000 / 控除合計 24,400 / 手取り 100,000（印字）

**良い**

```jsonc
{
  "gross": 120000,
  "net": 100000,
  "needs_review": true,
  "review_reason": "総支給120,000 − 控除24,400 = 95,600 が、印字された手取り100,000と一致しません。控除欄に読み取れていない項目があるか、印字が異なります"
}
```

**悪い**

```jsonc
{ "net": 95600 }
```

計算値で印字を上書きしています。**明細に書かれている額が正**であり、
合わないなら読み取り漏れを疑うべき場面です。

### 例3 — 通勤手当の扱い

**良い**

```jsonc
{
  "gross": 120000,
  "earnings": [
    { "name": "基本給", "amount": 115000 },
    { "name": "通勤手当", "amount": 5000 }
  ],
  "commute_allowance": 5000
}
```

総支給に含めたうえで、別途 `commute_allowance` にも記録します。
一定額までは非課税ですが、**限度額の判定はこの Skill の仕事ではありません**。

**悪い**

```jsonc
{ "gross": 115000 }
```

非課税だからと総支給から除いています。
**総支給は明細に印字された額をそのまま書きます。** 課税・非課税の区分は後段の話です。

## 迷ったとき

**書かない側に倒します。** 個人を特定できる情報は、
必要かどうか迷った時点で書かないのが正解です。
