# カード明細のパース

## この抽出の要点

**明細の合計が請求総額と一致すること。** ここが合わなければ取り込み漏れであり、
そのまま進めると二重計上の防止（第1部 §6）が成り立たなくなります。

**この検算は自分で実行してください。** 出力する前に足し算をして確かめます。

## 絶対に守ること

1. **明細行を1行も落とさない。** ページをまたぐ明細を見落としがちです。
   最終ページまで数えてください。
2. **カード番号を下4桁より長く書かない。**
3. **金額を推測で埋めない。**
4. **合計が合わないとき、行を足したり削ったりして合わせない。**

## 出力

```jsonc
{
  "schema_version": 1,
  "doc_id": "doc_2026-08-01_samplecard_a1b2c3",
  "type": "card_statement",
  "source": { /* 取り込み処理が埋めたもの */ },
  "origin": "electronic",
  "account": "Liabilities:Personal:CreditCard:Sample",
  "card_last4": "1234",
  "period": { "from": "2026-07-01", "to": "2026-07-31" },
  "statement_total": 84321,
  "debit_date": "2026-08-27",
  "transactions": [
    { "line_id": "L001", "date": "2026-07-14", "raw_description": "サンプルストア ワタダ", "amount": 1234 }
  ],
  "needs_review": false,
  "review_reason": null
}
```

`raw_description` は**明細に印字されたそのまま**を書きます。
表記ゆれの正規化は `rules/merchants.yaml` の仕事です。ここで整えないでください。

混在カード（事業と私用が混ざる）の `account` は `Liabilities:Personal:*` です。
`rules/accounts.yaml` の `namespace` に従ってください。

## 良い例 / 悪い例

### 例1 — 検算が合わない

明細の合計 82,000 / 請求総額 84,321

**良い**

```jsonc
{
  "statement_total": 84321,
  "transactions": [ /* 読み取れた行だけ */ ],
  "needs_review": true,
  "review_reason": "明細の合計82,000円が請求総額84,321円と一致しません（差2,321円）。読み取れていない行がある可能性があります"
}
```

**悪い**

```jsonc
{
  "statement_total": 82000
}
```

請求総額の方を明細に合わせて書き換えています。
**検算が意味を失い、取り込み漏れが永久に見つかりません。**

### 例2 — 分割・リボの表示

```
サンプル電機  分割 3回目/12   4,200
```

**良い**

```jsonc
{
  "line_id": "L014",
  "date": "2026-07-20",
  "raw_description": "サンプル電機 分割 3回目/12",
  "amount": 4200
}
```

その月の請求額だけを書きます。残債は別の話（第4部）です。

**悪い**

```jsonc
{ "raw_description": "サンプル電機", "amount": 50400 }
```

総額を書いています。**その月に請求されていない金額が帳簿に入ります。**

### 例3 — 日付が明細に無い

一部のカードは利用日を出さず、計上日だけを出します。

**良い**

```jsonc
{
  "line_id": "L003",
  "date": "2026-07-05",
  "raw_description": "サンプルサービス 月額",
  "amount": 980,
  "needs_review": true
}
```

`review_reason` に「利用日ではなく計上日を記載」と書きます。
突合（第1部 §6）は日付差3日以内で見るので、**ズレの理由が残っていることが効きます。**

**悪い**

明細に無い利用日を推定して書く。**根拠のない日付は突合を狂わせます。**
